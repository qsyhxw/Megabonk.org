Get everyone into the same co-op run

Pick your hero first, then use Co-op beside Enter. Host a room or join by code; the host enters the zone after everyone arrives. Current client text supports a party of up to five.[1]

Host or join, in order

  1. Open the original wow.aethus.pl directly; choose the hero and zone you intend to use.
  2. Open Co-op → Host. Enter an allowed lobby name; choose public discovery or private code-only access, player limit and an optional password.
  3. Send friends the code and password yourself. Joining players bring the hero selected on their own picker.
  4. For a public room, inspect the zone, no-password and unlocked-zone filters. An empty filtered list does not prove that the service is offline.
  5. When everyone has arrived, the host closes the window and enters the zone. The current client requires at least two players for a co-op run.

We inspected the lobby and Host panels but did not create a public room or complete a multiplayer session. Browser menu evidence does not establish parity with an older Windows archive.[1]

Match the refusal to the next check

ProblemNext check
Different versionCompare each player’s displayed game build; a similar download name does not prove matching versions.
Locked zone or difficultyCheck the selected class’s zone progress and the room’s difficulty. A lobby code does not bypass progression requirements.
Wrong password / no room with codeRecheck the supplied code and password with the host.
Full room / run already startedAsk the host to confirm capacity and run state.
Service or relay unreachableRecord the exact error and try the original host later; do not clear your save to fix a relay problem.

These branches interpret actual client messages. They are not a guarantee that reconnecting or reloading repairs every connection.[1]

Downed friends, reconnects and chat

The game instructs a living friend to stand beside a downed player to revive them; progress messages indicate who is bringing them back. Withering difficulty changes make revives slower and weaker, so do not assume one universal revive duration. Client text distinguishes a disconnected host, a disconnected player and a restored connection. Reconnection messages are not evidence of host migration or recovery after every party ends. Party chat is present in current text. We have not tested message delivery, shared loot/XP rules or a full revive cycle; those remain outside this workflow.[1]
