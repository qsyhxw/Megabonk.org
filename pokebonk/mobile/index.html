PokeBonk on your phone

Try the original browser game before looking for an APK. The current client includes touch controls, but source support is not proof that every Android phone or iPhone can run a full session smoothly.[1]

Checked October 26, 2026 · Beta v0.8.55 · Source-based guide

Use the browser route first

Open pokebonk.com — original browser game ↗ (external website, opens in a new tab) on the phone you intend to use. JavaScript and WebGL are required by the project’s entry page. Start with the device’s current browser rather than a reposted game inside another app.[1]

  1. Keep an existing Guest in its original browser profile. Do not clear it as a first troubleshooting step.
  2. Let the game load, then rotate to landscape if portrait leaves the controls cramped.
  3. Check movement, camera and the visible action buttons before committing to a longer run.
  4. Read the current graphics options if performance is poor; reduce workload one setting at a time and compare the result.

This is a source-based mobile setup guide. We did not test a physical iPhone or Android device, measure FPS, or verify a minimum supported OS or RAM specification.

What the touch layout changes

The current client defines an on-screen movement stick and touch actions for movement skills, interaction, aiming and Ultimate. It also includes touch settings and graphics controls. These definitions establish available controls; they do not establish device compatibility.[2]

Keyboard advice such as “press R” describes the desktop default. On a phone, use the corresponding displayed button rather than assuming there is a physical-key requirement.

Android APK and iPhone download questions

The project describes a browser release, and its legal notice says the game is not distributed on other platforms. In this source check we did not verify an official Android APK or App Store release.[3]

A third-party wrapper can open the same website while remaining an independent app. A familiar icon or name does not establish authorship. Before installing anything, check whether the original project explicitly links to that exact release. The browser route needs no APK.

If your browser offers Add to Home Screen, that is a browser shortcut or web-app flow; it is not evidence of a separately published native version. That flow was not device-tested here.

Choose the next step by the symptom

The October 25 notes describe a fallback that tries another graphics adapter if 3D initialization fails and shows a more specific explanation. Follow that displayed advice before erasing browser data. This is a documented recovery behavior, not a tested fix for every phone.[4]

Recent mobile changes also keep the “Not now” action visible at Bill’s Machine and allow cancellation when banishing. If you leave fullscreen, later runs should no longer re-enter it automatically. Check your current build before treating an older control screenshot as the present layout.

The original page requires JavaScript/WebGL and includes a Retry recovery action for failed client loading. Its recovery code reloads game resources rather than asking the player to erase all site data.[1][2]

Settings → Graphics now includes an FPS cap (unlimited, 30, 60, 90, 120 or 144). A lower cap is an option to compare for consistency or device workload; it does not increase the device’s maximum rendering ability. We have not measured power use or frame rates on a phone.

If the problem persists, report device model, browser version, game version and the visible error to PokeBonk community support ↗ (external website, opens in a new tab). Do not send passwords.

Controller, touch UI and crowded co-op effects

Version boundary: this guide covers the original pokebonk.com v0.8.55, checked October 26. Our Play window uses a separate third-party v0.8.27 source with separate progress. Newer co-op, Treasures and Archive changes may be absent there. Mechanics are SINGLE_SOURCE; no full-run, reward-claim or multiplayer completion test is claimed.

The public client contains gamepad handling as well as touch controls. Test movement, camera, interaction and menu selection separately; a browser detecting a gamepad does not prove its button mapping matches your device. Click/focus the game field before checking keyboard input, and use the original host when comparing a frame issue.[5]

A question visible in r/PokeBonk’s new-post listing asks to keep touch UI while using a gamepad (RHobbo, displayed 18h old in the saved listing). Its direct post was unreadable; we have no verified setting that forces this combination.[7] Record browser, controller and which UI disappears before asking support. Do not present a guessed toggle as a solution.

Version .51 adds teammate-attack visibility options: simplify or hide those effects when they obscure the arena. Compare one setting at a time. The existing FPS cap limits rendering work; it does not raise maximum device performance.[6]

No official numeric minimum OS/RAM or tested device matrix was found. Browser/WebGL prerequisites and a real-device performance guarantee are different claims. Menu lag is not proof that a downloadable native client exists.
