Set up PokeBonk on Steam Deck

Use the original browser game, then choose either the game’s controller bindings or a deliberate keyboard-and-mouse layout. A Steam Deck thread describes Brave and Heroic routes, but also reports stuck movement while turning the camera. This is a setup checklist based on those reports, not a Deck performance test.

Megabonk.org · Updated October 28, 2026 · v0.8.62 entry / v0.8.55 mechanics

Access and the specific corrections below checked November 6, 2026 against original v0.9.14. Other tables retain their stated review dates.

Choose a reported browser route

R3APER_PL’s r/SteamDeck post and replies, read October 28, describe these routes. They omit the game build and Deck hardware revision. The two routes come from different users in one thread, not independent benchmark datasets.

Map the actions before a long run

The OP maps movement to WASD, camera to mouse, A to E, X to R, a trigger to Space and other buttons to clicks or scrolling. Use that as a starting layout, then add missing actions rather than copying it as a complete preset.

Action to keep reachableKeyboard layout targetCheck
Movement / cameraWASD / mouseMove and turn together, then release both; movement should stop.
Jump / slideSpace / Left ShiftThe reported layout lacks an explicit slide binding; assign one if using keyboard emulation.

Those keyboard defaults come from the v0.8.55 public client. If using native gamepad input, inspect the game’s own bindings instead of layering the same action through both schemes. The current menu and any saved rebinding take priority.

If movement sticks while the camera turns

The OP reports continued movement until the analog stick is moved in that direction again. A second participant also asks about this symptom; a reply suggests Heroic/Gaming Mode, but the OP says Brave in Gaming Mode still shows it. The thread therefore does not establish a universal fix.

  1. In a low-risk area, check movement alone, camera alone, then both together.
  2. Record whether your layout emits gamepad input, keyboard/mouse input or both. Temporarily compare one input scheme at a time.
  3. Check whether the same profile behaves differently in Desktop Mode and Gaming Mode. Change one setting at a time.
  4. If the issue remains, report browser, launcher, game version, input layout and the exact reproduction sequence.

These are diagnostic comparisons, not confirmed repairs. Do not erase site data to troubleshoot a directional input problem.

Preserve the browser profile and set expectations

A new launcher or browser can have a separate session. Keep the working profile until you confirm access to the same game account. The original policy describes local session storage and deletion of inactive Guests after 60 days; it does not promise that different launchers share credentials.

Two users in the thread describe playing on Deck, but no reproducible FPS, battery, full-run or co-op measurements are supplied. We did not test a physical Deck. The original entry is v0.8.62 on October 28; the source for the action table is explicitly v0.8.55.

Choose the original app or the browser before remapping

The original project now offers PC apps. Its current Apps text lists Linux, and the v0.8.81 release names Steam Deck support. Open the original Apps menu to inspect the current package and instructions. The browser routes above remain historical community alternatives.

  1. Record whether you launched a browser, the original Linux app or an independent package.
  2. If startup fails, record the app version, system and exact error before applying a community command.
  3. If the menu opens but movement sticks, compare one input scheme at a time: native gamepad or deliberate keyboard/mouse emulation. Keep saved bindings and Steam Input in the report.
  4. Keep the working browser identity until the new route shows the intended original account.

We did not install an AppImage or test a physical Deck. No FPS, battery, universal startup command or browser-to-app transfer result is promised.
