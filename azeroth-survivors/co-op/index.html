Get everyone into the same co-op run

Pick your hero first, then use Co-op beside Enter. Host a room or join by code; the host enters the zone after everyone arrives. Current client text supports a party of up to five.

When a hero misses the run or a card is selected automatically

Checked 11 November 2026 against original v0.143.2. A new message says a hero that took too long to enter sits out this run and is in for the next one. If you see it, coordinate the next start with the host and check that your selected hero is ready before they enter.

The client also distinguishes a hero already in the party, a rejected host request with a stated reason, and a card taken for a hero that was too slow to choose. Read the actual party-chat message before retrying a join or interpreting a changed card as lost progress. Save the exact host-error reason when asking for help.

These prompts support the next checks above. They do not establish a universal reconnect timeout or recovery guarantee.

Source for this section · Aethus’s original client ↗. Displayed text checked in v0.143.2 on 11 November 2026.

Host or join, in order

  1. Open the original wow.aethus.pl directly; choose the hero and zone you intend to use.
  2. Open Co-op → Host. Enter an allowed lobby name; choose public discovery or private code-only access, player limit and an optional password.
  3. Send friends the code and password yourself. Joining players bring the hero selected on their own picker.
  4. For a public room, inspect the zone, no-password and unlocked-zone filters. An empty filtered list does not prove that the service is offline.
  5. When everyone has arrived, the host closes the window and enters the zone. The current client requires at least two players for a co-op run.

We inspected the lobby and Host panels but did not create a public room or complete a multiplayer session. Browser menu evidence does not establish parity with an older Windows archive.

Downed friends, reconnects and chat

The game instructs a living friend to stand beside a downed player to revive them; progress messages indicate who is bringing them back. Withering difficulty changes make revives slower and weaker, so do not assume one universal revive duration. Client text distinguishes a disconnected host, a disconnected player and a restored connection. Reconnection messages are not evidence of host migration or recovery after every party ends. Party chat is present in current text.

Read a ready check before changing zones

The v0.139 client includes a host-requested zone ready check with ready, not ready, no answer and called off states. A pending answer is different from a network refusal; a cancelled check is not proof that your save is broken.

  1. Read the named host and destination before responding.
  2. If you are not prepared to leave, choose not ready rather than relying on silence.
  3. If the check is called off, ask the host whether to try again; use the connection-error table above only when that error actually appears.

This verifies the client’s prompts, not a completed multiplayer session, permission rules or reconnect behaviour in v0.139.
